# ระบบยืมคอมพิวเตอร์และอุปกรณ์ V20 — Calendar Status, Expandable Events & API Resilience

## ปรับปรุงใน V20

- เมื่อเจ้าหน้าที่เปลี่ยนสถานะเป็น `คืนแล้ว` ปฏิทินจะแสดง `คืนแล้ว` แทน `อยู่ระหว่างยืม`
- รายการสถานะ `ยกเลิก` ไม่แสดงในปฏิทิน ล้างข้อมูลปฏิทินที่เก็บไว้ และคืนอุปกรณ์เป็น `พร้อมใช้งาน`
- ข้อความบนปฏิทินยึดสถานะที่ Admin เลือก: `รออนุมัติ`, `อนุมัติ`, `อยู่ระหว่างยืม` และ `คืนแล้ว`
- รายการ `ไม่อนุมัติ` และ `ยกเลิก` ไม่แสดง ส่วน `คืนแล้ว`, `คืนล่าช้า` และ `อุปกรณ์ชำรุด` แสดงเป็น `คืนแล้ว`
- เรียงรายการตามเลขอุปกรณ์แบบธรรมชาติ เช่น Notebook01, Notebook02, Notebook10 ทั้งในช่องวันและหน้าต่างรายการทั้งหมด
- แสดงปุ่ม `อีก X รายการ` เป็นสีแดงเพื่อให้สังเกตง่าย
- ข้อความ `อีก X รายการ` ในปฏิทินเป็นปุ่มเปิดรายการทั้งหมด และเลือกรายการเพื่อดูรายละเอียดได้
- จำกัดความกว้าง grid ช่องวันและแถบรายการให้อยู่ภายในกรอบปฏิทิน
- คำสั่งอ่าน API ผ่าน JSONP ลองเชื่อมต่อใหม่อัตโนมัติสูงสุด 2 ครั้ง และรอ Apps Script cold start ได้ 45 วินาที
- เก็บข้อมูลปฏิทินรายเดือนไว้ในเครื่องเพื่อแสดงผลทันที และยังใช้ข้อมูลล่าสุดได้เมื่อ API สะดุดชั่วคราว
- คงการอ่านชีต Equipment, Bookings และ BookingItems แบบครั้งเดียวต่อการค้นหาจาก V19
- แสดง `© 2026 IT Booking Com System. V.20` ใต้คำโปรยของระบบ
- เพิ่มเลข V20 ที่ title, header และป้ายมุมขวาล่างซึ่งมองเห็นได้ทุกหน้าจอ
- เพิ่ม cache-buster ให้ config.js และ API ระบุ V20 เมื่อเปิด URL /exec โดยตรง
- ไม่เปลี่ยนหัวตารางหรือโครงสร้างฐานข้อมูล

## รุ่นก่อนหน้า

## ปรับปรุงใน V17

- แก้ข้อความ `Unexpected token '<', "<!DOCTYPE" ... is not valid JSON` โดยตรวจคำตอบจาก API ก่อนแปลง JSON
- แสดงข้อความภาษาไทยที่เข้าใจง่ายเมื่อ Apps Script ส่งหน้า HTML หรือหมดเวลา
- Login retry อัตโนมัติ 1 ครั้งเมื่อการเชื่อมต่อสะดุดชั่วคราว และป้องกันการกด Login ซ้ำ
- กำหนด timeout เพื่อไม่ให้หน้าจอหมุนค้างไม่สิ้นสุด
- แก้สถานะ Loading เมื่อมีหลาย API ทำงานพร้อมกัน
- ลดการอ่านชีต Users ซ้ำในขั้นตอน Login และเขียนเวลา Login เพียงจุดเดียว
- คงฐานข้อมูล หัวตาราง และฟังก์ชันทั้งหมดจาก V16

## ปรับปรุงใน V16

- แก้ไฟล์จริงให้ช่องค้นหาทุกตารางใช้ event delegation ระดับหน้าเว็บ
- ยกเลิก inline event ที่ทำให้ช่องค้นหาพิมพ์ได้แต่ state ของตารางไม่เปลี่ยน
- รองรับการพิมพ์ภาษาไทยแบบ IME ตัวเลข ปุ่มล้าง และช่องค้นหาที่สร้างใหม่ภายหลัง
- คงหน้า Login โดยไม่แสดง Dashboard และคงโครงสร้างฐานข้อมูลเดิม

## ปรับปรุงใน V15

- แก้ช่องค้นหาของหน้า `ตรวจสอบสถานะคำขอ`, `คำขอยืม`, `อุปกรณ์`, `หน่วยงาน`, `ผู้ใช้งาน` และ `ประวัติ`
- เปลี่ยนการกรองให้ปรับเฉพาะผลลัพธ์ ตาราง จำนวนรายการ และเลขหน้า โดยไม่สร้างช่องค้นหาใหม่
- รองรับการค้นหาตัวเลข ภาษาไทย การพิมพ์แบบ IME และปุ่มล้างช่องค้นหา
- ปุ่มก่อนหน้า/ถัดไปปิดอัตโนมัติเมื่ออยู่หน้าแรกหรือหน้าสุดท้าย
- นำ Dashboard ออกจากหน้า Login และแสดง Dashboard หน้าเจ้าหน้าที่หลังเข้าสู่ระบบเท่านั้น
- แก้ช่องค้นหาทุกตารางให้ผูกกับตารางเป้าหมายโดยตรง ไม่สูญเสียตัวกรองเมื่อมีการวาดข้อมูลใหม่
- กรองจากค่าปัจจุบันในช่องค้นหาก่อนวาดตาราง รองรับทั้งภาษาไทย ตัวเลข และการพิมพ์ต่อเนื่อง
- คงการซ่อน Dashboard และส่วนจัดการทั้งหมดไว้จนกว่าจะเข้าสู่ระบบ
- แสดง `V15` ใต้ชื่อระบบเพื่อยืนยันว่าหน้า GitHub Pages อัปเดตแล้ว
- `Code.gs` ไม่เปลี่ยนจาก V13 จึงไม่ต้อง Deploy Google Apps Script ใหม่

## ปรับปรุงใน V13

- แก้ช่องค้นหาหน้า `ตรวจสอบสถานะคำขอ` และหน้า `อุปกรณ์` ให้กรองตารางทันทีทุกครั้งที่พิมพ์
- ใช้ตัวอ่านช่องค้นหาแบบระบุชื่อ control โดยตรง ไม่อาศัยตำแหน่งของ element ในแถบเครื่องมือ
- รองรับเหตุการณ์ `input`, `search`, `change` และ `compositionend` สำหรับภาษาไทยและปุ่มล้างช่องค้นหา
- เก็บข้อมูลต้นฉบับของแต่ละตารางไว้ก่อนกรอง ทำให้ผลลัพธ์ การแบ่งหน้า และ CSV ใช้ข้อมูลชุดเดียวกัน
- แสดง `V13` ใต้ชื่อระบบ เพื่อใช้ตรวจสอบว่า GitHub Pages โหลดไฟล์รุ่นใหม่แล้ว
- คงเงื่อนไขและการปรับปรุงทั้งหมดจาก V12

## ปรับปรุงใน V12

- หน้าอุปกรณ์ หน่วยงาน ประวัติ และผู้ใช้งาน มีค้นหา เรียงลำดับ เลือกจำนวนแถว แบ่งหน้า และส่งออก CSV
- แก้การค้นหาภาษาไทย เช่น `ทดสอบ` โดยจัดรูปแบบ Unicode และตัดอักขระแฝงก่อนเปรียบเทียบ
- รองรับการพิมพ์ภาษาไทยแบบ IME โดยไม่กรองกลางคำหรือทำให้ช่องค้นหาเสียโฟกัส
- CSV ใช้เฉพาะข้อมูลที่กรองและเรียงลำดับอยู่ในขณะนั้น
- แสดงจำนวนผลลัพธ์ที่พบและเลขหน้าปัจจุบัน

## ปรับปรุงใน V11

- แก้ช่องค้นหาในหน้า `แสดงคำขอยืม` และ `ตรวจสอบสถานะคำขอ` ให้พิมพ์ต่อเนื่องได้ โดยไม่สร้างช่องค้นหาใหม่ระหว่างกรองข้อมูล
- เพิ่มการหน่วงการค้นหา 180 มิลลิวินาที ลดการประมวลผลซ้ำทุกครั้งที่กดแป้น
- หน้า `อุปกรณ์`, `หน่วยงาน`, `ผู้ใช้งาน` และ `ประวัติ` ใช้ตารางมาตรฐานเดียวกัน
- ทุกตารางรองรับค้นหา เรียงลำดับ เลือก 10/20/50/100 แถว แบ่งหน้า และส่งออก CSV
- ไม่โหลดปฏิทินขณะเปิดระบบครั้งแรก ปฏิทินจะโหลดเมื่อผู้ใช้เปิดหน้าปฏิทิน
- เก็บรายการคำขอและข้อมูลผู้ดูแลไว้ชั่วคราว 60 วินาที ลดการอ่าน Google Sheets ซ้ำเมื่อสลับหน้า
- หลังเพิ่มหรือแก้ไขข้อมูล ระบบล้างข้อมูลชั่วคราวเฉพาะชุดที่เกี่ยวข้อง เพื่อให้แสดงข้อมูลใหม่ถูกต้อง
- คงเงื่อนไขและการปรับปรุงทั้งหมดจาก V10

## ปรับปรุงใน V10

- ช่องค้นหาคำขอยืมพิมพ์ต่อเนื่องได้โดยไม่เสียโฟกัส
- สถานะ `อุปกรณ์ชำรุด` บันทึกเป็นการคืนอุปกรณ์ เก็บรายละเอียดความเสียหาย และคืนเครื่องเป็นพร้อมใช้งาน
- รักษาเลข `0` นำหน้าของเบอร์โทรศัพท์ รวมถึงกู้เลขมือถือเดิมที่ถูกชีตตัดเลข 0
- ปฏิทินแสดงเวลาตามแต่ละวันเป็นเวลารับ เวลาคืน หรืออยู่ระหว่างยืม
- คงเงื่อนไขและการปรับปรุงทั้งหมดจาก V9

## ปรับปรุงใน V9

- ลดการอ่านชีตซ้ำระหว่างสร้างคำขอ โดยอ่าน `Settings`, `Bookings`, `BookingItems` และ `Equipment` อย่างละหนึ่งรอบ
- ลดการล้าง Cache ปฏิทินจากหลายปี เหลือเฉพาะเดือนที่ช่วงยืม–คืนได้รับผลกระทบ
- หลังบันทึกสำเร็จ อัปเดตจำนวน `รออนุมัติ` บนหน้าจอทันที และโหลดข้อมูลเต็มกับปฏิทินต่อเบื้องหลัง
- นำ Dashboard ออกจากหน้า `ปฏิทิน` และ `ตรวจสอบสถานะ`
- คง Dashboard หน้า `ยื่นคำขอ` ให้คำนวณตามประเภทและช่วงวันเวลาที่เลือก และคง Dashboard หน้าเจ้าหน้าที่
- ข้อความคำอธิบาย คำแนะนำ และข้อความแจ้งเตือนใช้สีแดงเพื่อให้สังเกตเห็นง่าย
- เก็บ `เปลี่ยนรหัสผ่าน` และ `ออกจากระบบ` ไว้เฉพาะเมนูย่อยใต้ชื่อผู้ดูแลระบบด้านขวาบน
- ไม่เปลี่ยนโครงสร้างชีตและไม่ลบข้อมูลเดิม

## ปรับปรุงใน V8

- แจ้งเตือนทันทีเมื่อวันเวลาคืนน้อยกว่าหรือเท่ากับวันเวลารับ และตรวจซ้ำฝั่ง Apps Script
- การ์ด “พร้อมใช้งาน” ในหน้ายื่นคำขอแสดงจำนวนอุปกรณ์ที่ยืมได้จริงตามประเภทและช่วงเวลาที่เลือก
- ย้าย “เปลี่ยนรหัสผ่าน” และ “ออกจากระบบ” ไปไว้ในเมนูย่อยใต้ชื่อผู้ดูแลระบบด้านขวาบน
- คำขอใหม่ทุกใบกำหนดสถานะเป็น `รออนุมัติ` ทันที และ Dashboard โหลดข้อมูลใหม่หลังบันทึก
- ไม่เปลี่ยนโครงสร้างชีตและไม่ลบข้อมูลเดิม

## ปรับปรุงใน V7

- ประเภทอุปกรณ์ในหน้ายื่นคำขอดึงจากข้อมูลที่มีอยู่จริงในชีต `Equipment`
- Dashboard หน้ายื่นคำขอคำนวณใหม่ตามประเภทและช่วงวันเวลาที่เลือก
- จำนวน “ว่างช่วงนี้” หักอุปกรณ์ที่ถูกอนุมัติ/รับไปแล้ว/คืนล่าช้าและเวลาทับซ้อนออก
- หน้า “ตรวจสอบสถานะ” เหลือช่องค้นหา เรียงลำดับ จำนวนแถว CSV และแบ่งหน้าเพียงชุดเดียวในแถวเดียว
- หน้าจอมือถือยังตัดเครื่องมือเป็นหลายแถวเพื่อให้อ่านและกดใช้งานได้สะดวก

## ปรับปรุงใน V6

- หน้าเลือกอุปกรณ์แสดง `อุปกรณ์เสริม` เฉพาะเครื่องที่มีข้อมูล
- กล่องสรุปอุปกรณ์ในแบบฟอร์มขอยืมแสดงอุปกรณ์เสริมของเครื่องที่เลือก
- หน้ารายละเอียดรายการในปฏิทินแสดงอุปกรณ์เสริมเมื่อมีข้อมูล
- แถบรายการในปฏิทินแสดง `ชื่ออุปกรณ์ : เวลายืม–เวลาคืน`

## ปรับปรุงใน V5

- หน้า “ยื่นคำขอ” เริ่มจากเลือกประเภทอุปกรณ์และช่วงวันเวลาที่ต้องการ
- แสดงเฉพาะอุปกรณ์พร้อมใช้งานและว่างในช่วงที่เลือกเป็นรูป Thumbnail
- คลิกรูปอุปกรณ์เพื่อเปิดแบบฟอร์มขอยืม โดยหนึ่งคำขอต่อหนึ่งอุปกรณ์
- นำไฟล์แนบออกจากแบบฟอร์มขอยืม
- หน้า Admin เพิ่ม/แก้ไขอุปกรณ์สามารถแนบรูป JPG, PNG หรือ WEBP ขนาดไม่เกิน 5 MB
- รูปบันทึกใน Google Drive และ URL บันทึกในคอลัมน์ `image_url`
- ฝั่งเซิร์ฟเวอร์ตรวจช่วงเวลาว่างซ้ำก่อนบันทึกคำขอ

## ปรับปรุงใน V4

- Dashboard ดึงข้อมูลใหม่ทันทีหลังส่งคำขอและหลังเปลี่ยนสถานะ
- ตัวเลขของวันเสาร์และวันอาทิตย์ในปฏิทินเป็นสีแดง
- การ์ด Dashboard ใช้สีพาสเทลแยกตามสถานะอย่างชัดเจน
- หน้ารายละเอียดจัดข้อมูลเป็นคอลัมน์ อ่านง่าย และยืดหยุ่นบนมือถือ
- แถบปฏิทินแสดง `ชื่ออุปกรณ์ : เวลาสิ้นสุดการยืม`
- แบบฟอร์มและฝั่งเซิร์ฟเวอร์ไม่อนุญาตให้ยืมย้อนหลัง
- ล็อกและตรวจเวลาซ้ำอีกครั้งขณะอนุมัติ อนุมัติได้เพียงคำขอแรก
- หนึ่งคำขอต่อหนึ่งอุปกรณ์ โดยเลือกจาก Dropdown รายการว่างตามช่วงเวลา
- นำปุ่มและแผง Dashboard ที่ซ้ำในหน้าเจ้าหน้าที่ออก

## ฟังก์ชันใหม่ใน V3

- ปฏิทินเลือกเดือน/ปีได้ เสาร์–อาทิตย์เป็นสีแดง และแต่ละอุปกรณ์มีสีประจำตัว
- คลิกแถบสีในปฏิทินเพื่อดูผู้ยืม ช่วงเวลา สถานที่ และวัตถุประสงค์
- แบบฟอร์มแสดงเฉพาะอุปกรณ์พร้อมใช้งานที่ไม่ถูกจองทับช่วงเวลาที่เลือก
- Dashboard แสดงบนทุกหน้าหลัก
- ตารางข้อมูลรองรับค้นหา เรียงลำดับ จำนวนแถว และส่งออก CSV
- ประเภทอุปกรณ์เลือกได้เฉพาะ `Notebook`, `PC`, `Projector`, `TV`
- เพิ่ม Cache ลดการอ่านชีตซ้ำ และปรับ Responsive สำหรับคอมพิวเตอร์ แท็บเล็ต และมือถือ

หากอัปเดตต่อจาก V8 ไม่ต้องรัน `setupSystem()` และไม่ต้องแก้โครงสร้างฐานข้อมูล

### อัปเดตจาก V18 เป็น V20

1. แทนที่ `google-apps-script/Code.gs` และสร้าง Deployment เวอร์ชันใหม่ โดยคง URL `/exec` เดิม
2. แทนที่เฉพาะ `github-pages/index.html` บน GitHub
3. เก็บ `github-pages/config.js` ตัวเดิมของระบบไว้ เพราะมี URL `/exec` จริงของคุณ
4. กด `Ctrl + F5` และตรวจว่าป้ายมุมขวาล่างแสดง `V20`
5. เปิด URL `/exec` โดยตรง ต้องเห็น `Equipment Booking API V20 is ready.`

### วิธีอัปเดต V17 (ประวัติ)

1. แทนที่ `Code.gs` แล้วสร้าง Deployment เวอร์ชันใหม่ โดยคง URL `/exec` เดิม
2. แทนที่ไฟล์ในโฟลเดอร์ `github-pages` บน GitHub โดยคงค่า `API_URL` เดิมใน `config.js`
3. ตรวจว่า Web App ตั้งค่า “ดำเนินการในนาม: ฉัน” และ “ผู้ที่มีสิทธิ์เข้าถึง: ทุกคน”
4. ไม่ต้องรัน `setupSystem()` และไม่ต้องแก้ข้อมูลใน Google Sheets

ชุดนี้แยกเป็น 2 ส่วน:

- `google-apps-script` ระบบหลังบ้าน เชื่อม Google Sheets และ Google Drive
- `github-pages` หน้าเว็บไซต์สำหรับนำขึ้น GitHub Pages

## 1) ติดตั้ง Google Apps Script

1. เปิด Google Sheets ที่มีชีต `Bookings`, `BookingItems`, `Equipment`, `Users`, `Departments`, `Logs`, `Settings`
2. ไปที่ **ส่วนขยาย > Apps Script**
3. นำ `google-apps-script/Code.gs` ไปแทนไฟล์ `Code.gs`
4. เปิด **การตั้งค่าโปรเจกต์** และเลือกแสดงไฟล์ Manifest จากนั้นนำ `appsscript.json` ไปแทนไฟล์เดิม
5. เลือกฟังก์ชัน `setupSystem` แล้วกด **เรียกใช้** 1 ครั้ง และอนุญาตสิทธิ์
6. ไปที่ **ทำให้ใช้งานได้ > การทำให้ใช้งานได้รายการใหม่ > เว็บแอป**
7. ตั้งค่า **ดำเนินการในนาม: ฉัน** และ **ผู้ที่มีสิทธิ์เข้าถึง: ทุกคน**
8. กดทำให้ใช้งานได้ แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec`

> เมื่อแก้ `Code.gs` ในอนาคต ต้องสร้างเวอร์ชันใหม่ในเมนูจัดการการทำให้ใช้งานได้ มิฉะนั้นเว็บจะยังใช้โค้ดเวอร์ชันเดิม

## 2) ตั้งค่าหน้า GitHub

1. เปิด `github-pages/config.js`
2. แทนที่ `PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE` ด้วย URL `/exec` ที่คัดลอกไว้
3. อัปโหลดไฟล์ทั้งหมดภายในโฟลเดอร์ `github-pages` ไปไว้ที่ root ของ Repository
4. ใน GitHub ไปที่ **Settings > Pages**
5. เลือก **Deploy from a branch**, Branch `main`, Folder `/ (root)` แล้วกด Save
6. รอประมาณ 1–3 นาที แล้วเปิด URL GitHub Pages ที่ GitHub แสดงให้

## หมายเหตุด้านความปลอดภัย

URL ของ Apps Script จะมองเห็นได้จากหน้าเว็บ ซึ่งเป็นเรื่องปกติของเว็บ API ระบบจึงจำกัดเฉพาะคำสั่งที่กำหนดไว้ และคำสั่งเจ้าหน้าที่ต้องใช้ Session Token อย่างไรก็ตาม ไม่ควรใส่ Secret หรือรหัสผ่านไว้ใน `config.js`

เวอร์ชันนี้เก็บรหัสผ่านเป็นข้อความธรรมดาตามความต้องการ ผู้ที่มีสิทธิ์เปิด Google Sheets จะสามารถเห็นรหัสผ่านในชีต `Users` ได้
